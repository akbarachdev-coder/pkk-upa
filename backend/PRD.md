Backend - Sistem Manajemen Keuangan (Laravel Finance System)
1. Ringkasan SistemSistem backend berfungsi sebagai RESTful API berbasis Laravel untuk mengelola pencatatan keuangan. Sistem ini mencakup autentikasi pengguna, manajemen dompet/rekening (wallets), kategori pemasukan dan pengeluaran, pencatatan transaksi, serta laporan rekapitulasi keuangan. Backend ini dirancang untuk dikonsumsi oleh frontend Next.js.2. Tech Stack & Konfigurasi Utama Autentikasi: Laravel Sanctum (Token-based API Authentication)Database: MySQL Format Response API: JSON Terstruktur (success, message, data, errors)3. Skema Database & Relasi ModelA. usersid (Primary Key, Auto Increment)name (String)email (String, Unique)password (String, Hashed)role (Enum: 'admin', 'finance_staff', 'user') — Default: 'user'created_at / updated_atB. wallets (Kategori Akun/Kas/Bank)id (Primary Key)user_id (Foreign Key -> users.id, On Delete Cascade)name (String, contoh: "Kas Utama", "Bank BCA", "Petty Cash")balance (Decimal 15, 2, Default: 0.00)description (Text, Nullable)created_at / updated_atC. categories (Kategori Transaksi)id (Primary Key)user_id (Foreign Key -> users.id, Nullable — Null jika kategori bawaan/global)name (String, contoh: "Gaji", "Operasional", "Transportasi")type (Enum: 'income', 'expense')created_at / updated_atD. transactions (Pencatatan Keuangan)id (Primary Key)user_id (Foreign Key -> users.id, On Delete Cascade)wallet_id (Foreign Key -> wallets.id, On Delete Cascade)category_id (Foreign Key -> categories.id, On Delete Restrict)type (Enum: 'income', 'expense', 'transfer')amount (Decimal 15, 2)transaction_date (Date)description (Text, Nullable)attachment_path (String, Nullable — untuk bukti transfer/nota)created_at / updated_at4. Spesifikasi API EndpointAuthentication (/api/auth)POST /api/auth/register $\rightarrow$ Registrasi pengguna baru.POST /api/auth/login $\rightarrow$ Autentikasi dan penerbitan Bearer Token.POST /api/auth/logout $\rightarrow$ Revoke token saat ini.GET /api/auth/me $\rightarrow$ Informasi pengguna yang sedang login.Wallets & Accounts (/api/wallets)GET /api/wallets $\rightarrow$ Daftar dompet/rekening beserta saldo saat ini.POST /api/wallets $\rightarrow$ Menambah dompet/rekening baru.GET /api/wallets/{id} $\rightarrow$ Detail dompet dan riwayat transaksinya.PUT /api/wallets/{id} $\rightarrow$ Memperbarui nama/deskripsi dompet.Categories (/api/categories)GET /api/categories $\rightarrow$ Daftar kategori pemasukan & pengeluaran.POST /api/categories $\rightarrow$ Membuat kategori kustom baru.Transactions & Reports (/api/transactions & /api/reports)POST /api/transactions $\rightarrow$ Mencatat transaksi baru (otomatis memperbarui saldo dompet).GET /api/transactions $\rightarrow$ Riwayat transaksi (dengan filter: rentang tanggal, jenis transaksi, dompet, dan kategori).DELETE /api/transactions/{id} $\rightarrow$ Mengapus transaksi (otomatis mengembalikan saldo dompet).GET /api/reports/summary $\rightarrow$ Ringkasan total pemasukan, pengeluaran, dan net cashflow pada periode tertentu.5. Aturan Bisnis & Validasi (Business Logic)Pembaruan Saldo Otomatis (DB Transaction): Setiap kali transaksi dibuat atau dihapus, saldo pada tabel wallets harus diperbarui secara konsisten menggunakan Database Transaction (DB::transaction).Transaksi income menambah balance.Transaksi expense mengurangi balance.Validasi Saldo: Sistem harus menolak transaksi bertipe expense jika jumlah pengeluaran melebihi saldo dompet yang tersedia (jika tidak diizinkan saldo negatif).Isolasi Data (Data Privacy): Pengguna hanya dapat melihat, menambah, dan mengedit data dompet serta transaksi milik akun mereka sendiri.6. Instruksi Eksekusi untuk AI AgentSaat mengimplementasikan kode ini, ikuti langkah berikut secara berurutan:Buat Database Migrations sesuai skema di atas lengkap dengan foreign key constraints dan tipe data decimal.Buat Eloquent Models (User, Wallet, Category, Transaction) beserta definisi relasi dan type casting.Gunakan Database Transactions pada Controller/Service Layer untuk menangani mutasi saldo di tabel wallets saat transaksi dibuat atau dihapus.Buat Form Request Classes untuk memvalidasi input transaksi (termasuk validasi format tanggal, jumlah minimal, dan keberadaan ID dompet/kategori).Implementasikan API Resources untuk memformat struktur respon JSON ringkasan laporan keuangan.
